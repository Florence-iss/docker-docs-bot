# Docker Docs Bot

A retrieval-augmented generation (RAG) chatbot that answers questions about
Docker using the official Docker documentation as its source of truth. Instead
of relying on a model's general knowledge, it retrieves the most relevant doc
pages for each question and answers from them, citing its sources.

This repo contains **two implementations** of the same idea:

1. A **local pipeline** — Docker docs chunked and embedded into a local vector
   database (ChromaDB), with answers generated by Claude.
2. A **cloud-native version on AWS Bedrock** — docs stored in Amazon S3 and
   indexed by a Bedrock Managed Knowledge Base, with answers generated by a
   Bedrock model. **This version is deployed and live.**

Ask it something like *"How do I install Docker?"* — it answers from the

## Architecture (AWS Bedrock version)

The deployed version is a fully cloud-native RAG system on AWS:

```
   Docker docs (Markdown)
          │  upload
          ▼
     Amazon S3                 bucket: docker-docs-bot
          │  sync
          ▼
   Bedrock Managed Knowledge Base
   (parses, chunks, embeds, and stores the vectors for you)
          │  Retrieve  → top-matching doc chunks
          ▼
     Python app  ──►  Bedrock model (Amazon Nova Lite)  ──►  grounded answer
     (Streamlit)          "generate an answer from these chunks"       + sources
```

**Two-step RAG, in plain terms:**
1. **Retrieve** — the app asks the Knowledge Base which doc chunks best match
   the question.
2. **Generate** — those chunks plus the question are handed to a cheap Bedrock
   model, which writes an answer grounded only in the retrieved docs (and says
   so when the answer isn't in them).

Using a **Managed** Knowledge Base means AWS handles the vector storage,
embedding model, and indexing — no separate vector database to run.

## Security & cost controls

The cloud version was built with a least-privilege, no-secrets-in-code approach:

- **Dedicated IAM user** (`docker-bot-app`) for the application — the root
  account is never used for day-to-day access.
- **No credentials in the code or repo.** Locally the app uses credentials from
  `aws configure`; when deployed, it reads them from Streamlit Secrets. Nothing
  sensitive is committed to Git.
- **Least-privilege permissions.** The app's IAM user is scoped to exactly two
  actions — retrieve from this one Knowledge Base and invoke the one model:

  ```json
  {
    "Version": "2012-10-17",
    "Statement": [
      {
        "Sid": "QueryMyKnowledgeBase",
        "Effect": "Allow",
        "Action": "bedrock:Retrieve",
        "Resource": "arn:aws:bedrock:us-east-1:<account-id>:knowledge-base/<kb-id>"
      },
      {
        "Sid": "InvokeMyModel",
        "Effect": "Allow",
        "Action": "bedrock:InvokeModel",
        "Resource": "arn:aws:bedrock:us-east-1::foundation-model/amazon.nova-lite-v1:0"
      }
    ]
  }
  ```

- **Cost guardrail.** An AWS Budgets alert emails on approaching a small monthly
  spend limit, so there are no surprise bills.

## How it works (local ChromaDB version)

The local pipeline is a set of small, single-purpose scripts:

1. **`load_docs.py` / `inspect_docs.py`** — sanity-check the raw markdown docs.
2. **`chunk_docs.py`** — splits each doc into ~1000-character chunks (with
   overlap) and writes them to `chunks.json`.
3. **`build_vectorstore.py`** — embeds each chunk and upserts it into a
   persistent ChromaDB collection (`chroma_db/`).
4. **`search.py`** — a CLI to inspect raw vector search results (no LLM call),
   useful for debugging retrieval quality.
5. **`rag.py`** — the chatbot as a CLI: retrieves relevant chunks and asks
   Claude to answer using only that context, citing sources.
6. **`app.py`** — the same chatbot as a Streamlit web UI, with chat history and
   an expandable sources list per answer.

And the Bedrock-backed version:

7. **`ask_docker_bot.py`** — CLI: retrieves from the Bedrock Knowledge Base and
   generates an answer with a Bedrock model (Amazon Nova Lite).
8. **`docker_bot_app.py`** — the same Bedrock-backed bot as a Streamlit web UI
   (this is the deployed app).

## Setup

**Local (ChromaDB + Claude) version**

1. Clone the Docker docs content into `data/docs` (markdown pages are expected
   under `data/docs/content`):

   ```
   git clone https://github.com/docker/docker.github.io data/docs
   ```

2. Create a virtual environment and install dependencies:

   ```
   python3 -m venv venv
   source venv/bin/activate
   pip install -r requirements.txt
   ```

3. Add your Anthropic API key to a `.env` file in the project root:

   ```
   ANTHROPIC_API_KEY=your-key-here
   ```

**Bedrock version**

- Upload the docs to an S3 bucket and create a Bedrock Managed Knowledge Base
  pointing at it, then set `KNOWLEDGE_BASE_ID` in `ask_docker_bot.py` and
  `docker_bot_app.py`.
- Provide AWS credentials via `aws configure` (local) or Streamlit Secrets
  (deployed) — no `ANTHROPIC_API_KEY` needed for this version.

## Usage

Local version — build the chunk file and vector store (run once, or again after
docs update), then run:

```
python chunk_docs.py
python build_vectorstore.py
python rag.py                 # CLI
streamlit run app.py          # web UI
python search.py              # inspect raw retrieval, no LLM
```

Bedrock version:

```
python ask_docker_bot.py          # CLI
streamlit run docker_bot_app.py   # web UI
```

## Running with Docker

The Dockerfile packages the Streamlit UI along with a prebuilt vector store, so
run `chunk_docs.py` and `build_vectorstore.py` locally first to generate
`chroma_db/` before building the image.

```
docker build -t docker-docs-bot .
docker run -p 8501:8501 -e ANTHROPIC_API_KEY=your-key-here docker-docs-bot
```

Then open `http://localhost:8501`.

## Notes

- The vector store (`chroma_db/`), chunk cache (`chunks.json`), and cloned docs
  (`data/`) are gitignored since they're large and reproducible from the steps
  above.
- `build_vectorstore.py` uses `upsert`, so it's safe to re-run without
  duplicating chunks.
- The Bedrock version currently indexes the Docker **get-started** docs. Adding
  more (e.g. `reference`, `manuals`) is just another S3 upload and a re-sync of
  the Knowledge Base.
